### Component code contract

- Return only `InteractiveComponentDraft` JSON. Copy task, knowledge-unit and ContextPack IDs exactly. Use only source references supplied by the task and ContextPack.
- Runtime fields such as `plan_id`, `run_id`, `accepted_content_artifact_id` and top-level `source_refs` are bound by the caller and do not belong in the draft.
- When `spec` is null, provide a specific `not_needed_reason`. When `spec` is non-null, omit `not_needed_reason` entirely.
- The only component_type is `generated_html`. Supply component_id, title, learning_objective, source_refs, accessibility (aria_label, description, observation), controls, test_actions, annotations, libraries, html, css and javascript. Use annotations=[]; put visual labels directly in the markup.
- html, css and javascript are fragments, not a full document. Do not include script/style/iframe/object/embed tags in html, or closing script/style tags in code fields. Limits: html 20000, css 12000, javascript 20000 characters.
- Use ordinary DOM, SVG or Canvas as appropriate. libraries=[] by default; optional local runtimes are `jsxgraph` (global `JXG`, interactive geometry), `echarts` (global `echarts`, statistical charts, networks and trees) and `d3` (global `d3`, custom SVG/data/step visualizations). Choose the smallest suitable set; usually zero or one library. Do not repeat library names. All declared libraries are loaded before your javascript runs. No imports, downloads, external resources, network calls or parent-page dependencies. The renderer owns the sandbox and CSP.
- Controls are a browser-test protocol, not subject-specific component types. A toggle has kind="toggle", control_id, label and boolean default_value; a range has kind="range", control_id, label, minimum, maximum, step and numeric default_value. Expose each as a real HTML input with data-component-control="same control_id", its label, type and initial value.
- Supply at least one test action for each declared control: action="toggle" or "set_range", control_id, value and expected_text. Implement the corresponding event listener. expected_text must become visible after the action; do not place test answers in hidden elements or scripts. Keep feedback accessible (for example aria-live).
- Interaction must serve one supported learning objective and preserve textbook facts. Do not fabricate domain facts. If the evidence cannot support a useful, verifiable interaction, return spec=null rather than a decorative or empty component.

- Library usage: JSXGraph: `JXG.JSXGraph.initBoard(id, options)`. ECharts: give the container explicit width/height, call `echarts.init(element, null, {renderer: 'svg'})` then `setOption`; enable `aria: {enabled: true}`, update with controls and resize on window resize. D3: use `d3.select`, scales, shapes, hierarchies or layouts with in-memory source-supported data; use SVG title/description and visible text feedback. Do not call d3.fetch/d3.json or fetch remote assets. Library drawings do not replace accessible explanations or testable control feedback.
