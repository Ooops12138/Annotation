# 03 大纲提取 / 教材理解 Agent

## 1. 目标

将用户提供的一本或多本教材转换为可供后续 Agent 使用的 **Learning Blueprint**。

核心任务不是提取目录，而是理解教材中的教学结构。

## 2. 输入

- 一本或多本教材
- 可选的用户学习目标、学习对象或学习范围

## 3. 输出

输出一份统一的 Learning Blueprint，包括：

- 章节与层级结构
- 知识单元
- 知识之间的依赖关系
- 重要定义、定理、公式和方法
- 典型例题、证明和论证材料
- 教材来源
- 学习重点与建议顺序

## 4. 建议流程

```text
教材解析
   ↓
章节识别
   ↓
知识单元提取
   ↓
教学关系识别
   ↓
前置知识 / 依赖关系整理
   ↓
多教材对齐（如有）
   ↓
形成 Learning Blueprint
   ↓
完整性检查
   ↓
发现问题后回退修正
```

## 5. 单本教材

以教材自身的章节结构和教学脉络为主要依据。

Agent 重点识别：

- 每章解决什么问题
- 每节引入什么知识
- 知识点之间如何衔接
- 哪些例题承担解释作用
- 哪些证明或推导承担理解作用
- 哪些知识是后续内容的前置条件

## 6. 多本教材

首先确定主教材，再将其他教材映射到主教材的学习结构中。

重点处理：

- 同一知识点的不同组织方式
- 主教材缺失而补充教材存在的内容
- 不同教材的深度差异
- 不同例子和解释方式

Agent 的目标是形成一份统一学习蓝图，而不是简单合并目录。

## 7. 检查与迭代

至少需要检查：

- 是否遗漏章节中的重要知识点
- 是否错误合并不同概念
- 是否丢失关键前置关系
- 是否将例题、证明等教学材料错误地当成知识点
- 多教材之间是否存在明显冲突

发现问题后允许回到前面的抽取步骤重新处理。

## 8. 暂不固定的实现细节

以下内容后续单独设计：

- PDF / EPUB / HTML 的解析方式
- Chunk 策略
- RAG 实现
- Prompt
- Blueprint Schema
- 图结构的具体表示
- Agent 的工具集合
- loop 的最大轮数和停止条件

## 9. 最重要的判断标准

大纲 Agent 的成功标准不是“目录提取得很像”，而是：

> 后续 Agent 仅依赖 Learning Blueprint 和必要的教材检索，能否生成一份完整且学习路径合理的章节内容。
