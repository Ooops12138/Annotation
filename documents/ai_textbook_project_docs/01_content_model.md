# 01 内容体系与 Learning Blueprint

## 1. 目的

定义教材内容经过 Agent 理解后，用什么结构承载，并作为后续内容生成的统一中间层。

## 2. 基本单位

系统不直接以“页面”作为最小内容单位，而以 **Knowledge Unit（知识单元）** 作为主要组织单位。

知识单元可以是：

- 概念
- 定义
- 定理 / 命题
- 公式
- 方法
- 例题
- 证明 / 推导
- 应用
- 易错点
- 补充知识

## 3. Learning Blueprint

学习蓝图至少表达以下信息：

```text
Chapter
 ├── Section
 │    ├── Knowledge Unit
 │    │    ├── core idea
 │    │    ├── prerequisites
 │    │    ├── related units
 │    │    ├── examples
 │    │    ├── proofs / reasoning
 │    │    └── source
```

蓝图同时承担三项职责：

1. 记录教材知识结构；
2. 描述学习顺序和依赖关系；
3. 为后续生成 Agent 提供任务边界。

## 4. 多教材

多教材情况下，蓝图需要保留来源信息，并区分：

- 主教材内容
- 补充教材内容
- 教材之间的不同组织方式
- 可选拓展内容

目标是形成统一学习路径，而不是将多本教材简单拼接。

## 5. 来源追踪

每个重要知识单元应能够追溯到对应教材及章节。后续生成内容应保留这种来源关系，以支持检查、回溯和重新生成。

## 6. 设计边界

本阶段只规定蓝图需要表达什么，不规定具体 JSON Schema、数据库结构或图数据库实现。这些属于后续实现设计。
