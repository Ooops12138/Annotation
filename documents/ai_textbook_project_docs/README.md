# AI教材学习文档生成 Agent

版本：v1.0
定位：个人学习 / 技术练习项目

## 1. 项目定义

本项目是一个 AI Agent 系统：输入是任意学科的教材（一本或多本），输出是一份面向学生、自学者和基础薄弱入门者的在线学习文档。Agent 理解教材内容与结构，生成一份可在线阅读、学习和练习的数字化学习文档，并叠加背景知识拓展、图片图表、交互组件、测验，再加一层"审核标注"——对内容中的事实性风险点、以及存在学术分歧的立场性表述进行标注，但不越权替用户下结论。

教材是系统的主要知识来源。系统在理解教材的基础上，对知识进行重新组织、解释、补充和数字化呈现，使学习者能够通过网页完成阅读、理解、练习和复习。

项目定位为**个人学习与技术练习项目**：借助一个真实、有一定难度的场景，完整地练一遍"多智能体内容生成流水线"的设计与实现——包括内容生成、事实核查、多模态生成、交互式前端、质量评估等模块。

项目名称：

中：书注

英：Annotation

核心流程：

> 教材 → 教材理解 → 学习蓝图 → 学习内容生成 → 数字化呈现 → 质量检查 → 在线学习文档

## 2. 核心目标

项目首先验证一个核心能力：

> 给 Agent 一本或几本教材，它能否理解其中的知识体系，并将其转化为结构清晰、内容完整、适合学习的在线文档。

重点验证：

- 长文档理解与知识结构提取
- 多教材融合
- Agent loop 与任务编排
- 学习内容生成
- 交互内容生成
- 自动检查与迭代

## 3. 输出形式

最终输出是一份在线学习文档，可以包含：

- 知识讲解
- 教材中的典型例子、证明或论证
- 补充背景与应用
- 图片与图表
- 交互组件
- 测验与练习
- 来源信息

不同内容是否生成、生成到什么程度，由 Agent 根据学习需求决定。

## 4. 内容来源原则

教材是核心来源。

一本教材：以该教材为主线。

多本教材：确定主教材，其他教材作为补充，用于补充知识、解释、例题和不同组织方式，不机械拼接目录，也不强制取交集。

外部资料：用于补充和核查，不取代教材的课程主线。

## 5. 核心中间层（暂定）

项目采用统一的 **Learning Blueprint（学习蓝图）** 连接“教材理解”和“内容生成”。

学习蓝图描述：

- 章节与知识单元
- 概念、定义、定理、公式等核心内容
- 知识之间的前置与依赖关系
- 例题、证明、论证等教学材料
- 教材来源
- 学习顺序与重点

后续 Agent 原则上以学习蓝图为共同上下文，而不是分别重新阅读整本教材。

## 6. Agent 架构

系统由一个顶层编排 Agent 和若干专用 Agent 组成。

```text
用户教材
   ↓
教材理解 / 大纲提取 Agent
   ↓
Learning Blueprint
   ↓
课程编排 Agent
   ├── 讲解生成 Agent
   ├── 背景补充 Agent
   ├── 交互内容 Agent
   ├── 测验生成 Agent
   └── 审核 Agent
   ↓
学习文档整合
   ↓
在线呈现
```

这里的 Agent 划分用于定义职责边界，不预设具体实现方式。后续可以根据实验结果合并、拆分或取消 Agent。

## 7. 第一阶段范围

第一阶段只验证一门学科的一章，完整跑通：

> 教材导入 → 教材理解 → 学习蓝图 → 讲解生成 → 测验 → 基础审核 → 在线呈现

交互组件、复杂多教材融合等功能可以作为后续扩展。

建议从数学分析开始，选择一章知识结构清晰、可验证性较强的内容作为 POC。

第一阶段不做：账号体系、协作功能、移动端、多学科全面覆盖、大规模部署。

## 8. 项目边界

本项目首先关注“教材驱动的学习文档生成”，不以通用教育平台、通用知识库或自动课程市场为目标。

所有具体的 Prompt、Agent loop、数据 Schema、RAG 策略、评估指标和技术选型，均放在子文档中单独设计。
